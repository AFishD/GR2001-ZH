## 1. 结论（三句话版）

1. **错位是真的**（不是反汇编推断的假警报）——实机 A/B 已闭环：按"引擎格"涂实心块，
   游戏里那个字**真的变成方块**；而"毫米"这类词在现役盘上**确实显示成别的字**。
2. **成因不是"行相位"**，而是 **flat 容器 ↔ 引擎图 的段错位**（每段 48B 包头 ⇒ 6 格/段）。
   历史补丁给行 19..24 用的相位 `PHI=2/0` 是错的（真值 = `6×(段号+1)`）。
3. **已修 + 已验证**：新盘 `GR_ZH94` 上 1429/1429 个字符的字形都在引擎采样格上
   （`dump_font` 的 `grid_row_alignment` 全行 drift = 0），实机截图确认受影响的字显示正确，
   未受影响的界面与现役盘逐像素一致。

## 2. 现象与机制

### 2.1 引擎怎么取字（反汇编 + 实机双证）

现役 ELF 的 cctc cave（hook `0x21ADE0` → `0x417050`）：

```
单字节码 (lead==0):  a1 = code - fld[8]                     ; 0x20..0xFF ⇒ a1 = 0..223
对偶码  (lead!=0):   a1 = (lead-0xA1)*94 + (trail-0xA1) + 224
if (a1 < fld[17]=224)  → **FT 记录表**: 用记录矩形 (u0,v0,u1,v1) 当采样窗
else                   → **网格格**: slot = a1-224; row = slot/62; col = slot%62
                                   U0 = 16*col ;  V0 = 2 + 16*(row + 3*[row>=12])
```

⇒ **对偶码采样"引擎图的 (16×col, yrow) 格"，没有任何行相位；单字节码采样 FT 记录矩形。**

### 2.2 像素容器是 GIF 封包流（round44 查实，本轮沿用）

`COMMON.PAK → new_font_revised` 的像素区 = 8 段，每段 `[PT tag 16B][A+D TRXPOS 16B][IMAGE tag 16B]`
+ 64 行数据（TRXPOS.y = 0/64/…/448）。硬件把包头当 **DMA 命令**吃掉 ⇒ 引擎看到的图是
"每段数据放回 TRXPOS 指定的行"的那张图。字节级换算式（可逐字节复核）：

```
引擎像素 (x,y)  ↔  容器字节 = 512*y + x/2 + 48*(y//64 + 1)
⇒ flat 列 = (引擎列 + 6×(段号+1)) mod 64   (满了进下一行)
```

### 2.3 错位是怎么来的

历史写盘脚本按 **flat 口径**写字形：`flat 列 = (col + PHI[row]) mod 64`，`PHI` 是 round41
**在旧 dump 的错位视图里拟合**出来的表。行 0..18 恰好 `PHI[row] = 6×(段号+1)` ⇒ 两边重合，一直是对的；
行 19..24 的 `PHI = 2 / 0` ⇒ 字形落到 **同排别的列**：

| grid 行 | yrow | 旧 PHI | 真值 6×(段号+1) | 字形实际落在引擎图的哪 |
|---|---|---|---|---|
| 19, 20 | 354, 370 | 2 | **36** | col 0..33 → (col+30, 上一行)；col 34..61 → (col−34, 本行) |
| 21, 22, 23, 24 | 386…434 | 2 / 0 | **42** | col 0..39 → (col+24, 上一行)；col 40..61 → (col−40, 本行) |

### 2.4 ⚠ 本轮新查实的一件事：行 19 的 col 0..33 是**单字节码的地盘**

用 方正像素16 模板**逐格辨认**引擎图（`a5_ident.py`），行 19 的 col 0..33 里
**err=0 完美命中**的是单字节码 0xDB..0xFE 的字形：

```
后放置不切命向和退装枪标使员人爆选这个设手随视游目前指更它有雷何上
```

而它们的 FT 记录矩形（`(0,354,16,370)`, `(16,354,32,370)`, …）**正是这些格** —— 两条路都指向同一格：

* 单字节码 0xDF「切」→ 记录矩形 (64,354) → 引擎格 (19,4)；
* 对偶码 slot 1182（`米`，码 0xAD 0xD7）→ row19 col4 → 引擎格 (19,4)。

⇒ **米 与 切 抢同一格，而格里是"切"的字形** ⇒ 游戏里 `米` 显示成 `切`、`毫` 显示成 `命`。
行 19 的 30 个已用槽（col 4..33）**全部**踩在这个禁区里 ⇒ **单纯搬像素修不了，必须改码位**。

#### 4.1.1 ⚠ 本轮自查抓到的一个坑（已修）：图标码的记录矩形也在带里

`a3_bands.py` 早就算出 **4 条 FT 记录矩形落在行 21/22 的带里**：
`0x7B (89,395,94,408)`、`0x7D (97,395,102,408)`、`0xE7 (121,395,128,408)`、`0xF1 (128,395,135,408)`，

⇒ 清带时把它们擦了。**实机症状**：M18 详情页描述框上下那两个滚动箭头变暗（差异 95 像素）——
