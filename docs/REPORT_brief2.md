## 三、根因链 (静态定案) — 用户截图的下移缺陷为何已在 ZH61 消失

- `DrawString` 内层 0x219A70: `f21 = (float)CharHeight` (0x219ADC → **V18B cave 0x417200**:
  CH==26→16), 字形 quad 角 y = y+f21 (0x219B90)。**V18B 之前** quad 高 = 26px, 16px 字形
  墨迹随之压低/拉伸, 底部溢出行槽 ~10px — 与用户 GR_ZH15 时代截图
  `test_results/GR_ZH15.iso/任务简报-未汉化+字体显示下移超出原先区域.png`
  ("字体显示下移超出原先区域") 吻合。
- `IkeBaseButton::DrawText` (0x21D830) 逐分支 (gdis62 反汇编):
  - style 3/2: StringWidth 居中/右对齐 (x 向, CH 无关);
  - style 0xC (垂直居中): `y += d9 + (H−15)/2` — **硬编码 15** (0x21D940 addiu v0,v1,-15;
    0x21D934 的 CharHeight 调用结果被覆盖, 是死调用), CH 无关;
  - **style 8 (底对齐): `y = anchorY + d9 + H − CharHeight` (0x21D974–0x21D998) — CH 相关**,
    V18B 前该分支墨迹整体偏低 10px。简报按钮行实测走默认分支 (Δ=+3 而非 +10), 但
    style-8 的存在说明 CH 改动对该函数族的影响面与 V18B 的修复面一致。
- 结论: 用户所见缺陷属 **V18B 修复族**, 已在 ZH57–ZH61 期间的 V18B cave 修复;
  本轮双盘墨迹对照是该修复在简报屏上的首次直接实证。

### 22.2 机理定案 (RAM + 反汇编, 推翻"场景资源 y 记录"假设)

逐盘字节比对 (MENU.IMG 全部 686 条目 / GR.IMG 全部 4070 条目含 NTSC_IKE.RES/IKE.RES / ELF):
**场景资源 EN 与 ZH61 逐字节相同** (差异仅: 字体/字库/文本/记忆卡贴图/STRINGS.TXT + ELF 已知 cave)。
简报行 y **不在盘上** — RSComponent::ReadResource 反汇编证实序列化字段不含 [0x38]/[0x3c]/[0x48]/[0x4c]
(位置由父布局运行时计算, 且双盘 RAM 结构逐字节一致: ay=286/307/328/349, W=568, H=31, [0x4c]=0, [0xd9]=0)。

行 y 真正来源 = `IkeBaseButton::DrawText` (0x21D830) style-0xC 垂直居中分支:

```
EN : y = ay + [0x4c] + [0xd9] + (H − CharHeight(26))/2  → 286+0+0+2 = 288/309/330/351
ZH61: y = ay + [0x4c] + [0xd9] + (H − 21)/2             → 286+0+0+5 = 291/312/333/354
      └ ELF cave 0x21D940 硬编码 21 (16px 字形居中常数), CharHeight 调用成死调用
```

8/8 行实测与公式精确吻合 (行 2-4: ay=307/328/349 同式)。表头 +4 同族 (ELF 0x4176A0
被替换为 `return 16`), PDA/训练 +5 来自另两处 DrawText cave (0x2071B4 等硬编码 −16)。

### 22.3 补偿杠杆 — 资源字节 (零 ELF)

行 y 公式中唯一**可序列化**的自由变量 = 记录内 H 字段 (ReadResource 读入 [0x44])。
NTSC_IKE.RES (MENU.IMG 内, cdvd.log 实证运行时唯一加载份; GR.IMG 内两份从不读取)
