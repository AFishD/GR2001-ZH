## 0. 一页结论

```
① ★★★ 钩子被**彻底排除**。两条独立的空结果，方向相反、结论一致：
   (a) 从汉化盘上把 **49 处钩子全撤掉**（HK_01_all_text_off）⇒ fps 一动不动：
       HK_01 = 95.04 fps vs 同批基底 = 95.10 fps（−0.06%）；逐阶段比也全线重合。

       ————————————————  合计 +3.01 ms/帧 = 基底同批实测的 +3.01 ms/帧

③ ★★ 交叉推论（给用户该优先测哪张盘）：
   fps 信号**不指向任何一张 HK 盘**（5 张全部与基底无差异）⇒ 优先级要按**数据侧**排，
```

## 1. 方法（逐字照前一位的配方，保证可比）

### 1.1 命令形状（每条臂只换 `--arm` / `--iso`）

```powershell
python work\builds\GR_FPSBISECT\tools\run_arm_bisect.py --arm <名> `
  --iso <ISO> --frames 32000 --snap 60 --perf 1 --nav nav_play_v4.txt `
  --tag fpsbisect --wait-clear-s 2400
```

`run_arm_bisect.py` = **逐字复用** `work\builds\GR_FPS\tools\run_arm.py`（同名参数、同一
`pcsx2-gsrunner.exe`、同一 `-grmaxframes 32000 -grsnap 60 -grinput nav_play_v4.txt -perf`、
同一仓模板记忆卡、每臂**全新记忆卡副本**），**只改两处**：

| 改动 | 为什么 |
|---|---|
| `ROOT = work\builds\GR_FPSBISECT\out`（原为 `GR_FPS\out`） | 本轮写入范围是 `GR_FPSBISECT\**`，`GR_FPS\**` 保持只读 |
| 起跑前等"零 pcsx2 进程"**超时即拒绝起跑**（写 `RUN.txt` 的 `exit=9 / aborted=wait_timeout`），而不是原版的"仍被占着也硬跑" | 被别人占着跑出来的 fps 是污染读数，对结论没有价值 |

* `nav_play_v4.txt` **原样只读复用**（`GR_FPS\tools\`），一个字节都没改 ⇒ 轨迹与前一轮逐帧相同（§1.4）。
* `--snap 60`（不是 `--snap 0`）：任务书写 `--snap 0` 是为了省盘，但 `f300–540` 段的局部 fps
  **必须**靠快照文件 mtime 才能算（`bands.py`/`subband.py`）。实测每臂全量快照 ~110 MB（529 张）
  （全部 23 臂合计 2,521 MB，抽数后已删；`GR_FPSBISECT` 现为 1,085 MB），故**保留 `-grsnap 60`** 以拿到
  §5 的判据；跑完抽数后**快照已删**（§7.4）。这是对任务书 `--snap 0` 的**有意偏离**，理由如上。
* 每臂跑完立刻删掉 gsrunner 默认 needle 的 EE/IOP RAM 转储（`*_eeram.bin` / `*_iopram.bin`，
  每臂 ~408~476 MB，与本结论无关、可随时再生）。

### 3.2 这与任务书给的候选（H-A"回归来自 ELF 补丁本身"）相反，必须明说

`docs\REPORT_FPS_ZH113b.md` §10 的 **H-A（最高优先）** 推断"这 25~40% 回归来自 ELF 补丁本身"，
