## 1. 任务 A —— 单格字库 + 逐字与图集纹理比对（用户点名要的工具）

### 1.1 工具与产出

`tools/iso_build/single_cell_font.py`（只读盘）。对 charset 里**每一个字符**：

1. 按**引擎口径**从图集取出一格 —— 对偶码走引擎格位公式 `x=16*col, y=2+16*(row+3*[row≥12])`（无相位）；
   单字节码 / ASCII 走 `FONT.RES` 的 **FT 记录矩形**（`(u0,v0,u1,v1)` 原值 = 引擎采样窗）；
2. 用 `third_party/fonts/方正像素16.ttf` 按 `gen_font16.render16()` **同款配方**渲染期望位图
   （PIL truetype 16px，draw origin (8,8)，窗 = `canvas[8:24,8:24]`，阈值 <128）；
3. **逐像素比对** ⇒ 每格给 `match / diff_px / 差异类型`；
4. 差异一律**再查一步**：全盘滑窗搜索"这个字的模板到底在图集哪儿"（矩阵乘加速的 IoU 预筛 + 精确 XOR 复核）。

产出（`--out`，默认 `<盘目录>/font_single_cell`）：

| 文件 | 内容 |
|---|---|
| `single_cell_font.png` | **单格字库总表**：一字一格，格内是**盘上真正采到的那 16×16 像素**；边框色 = 结论（绿=逐像素一致 / 黄=有差异 / 红=错误）；每格下标注字符与码位 |
| `single_cell_font_expected.png` | 同版面的**期望位图**总表（方正像素16 16px 模板），对照用 |
| `single_cell_report.json` / `.md` | 逐格结果 + 汇总（匹配率 / 不匹配清单及定性）+ 交叉核对 |
| `mismatch_sheet.png` | 只放不匹配的字，放大三栏：左=盘上格 / 中=模板 / 右=差异（红=盘上多、蓝=模板多） |
| `single_cell_selftest.json` | ★ 反向自证的证据（见 §1.3） |

**判据是紧的**：`diff_px == 0` 才算 `match`，**不用** ±4/±2 容差窗
（round46 的 6 个空白字、round50 的 10 个丢行字都是被宽容差蒙掉的）。

差异类型：`match` / `empty_disk` / `read_mismatch` / `lost_rows` / `row_shift` / `col_shift` /
`missing_ink` / `extra_ink` / `different_glyph` / **`displaced_glyph`（字形在盘上，但不在引擎采样的那一格）** /
`template_missing`（字体渲染不出 ⇒ 只做几何判据）/ `by_design` / `engine_icon`。

## 2. 任务 B —— 重排为什么画错字（机理已闭环）

### 2.1 `repack_font.py` 的重编码覆盖范围

| | 内容 |
|---|---|
| 重排会改的 | ① charset JSON 的 `pair_of`（逐字换码位）；② 图集像素（字形搬到最前面的可用格、未使用区清零）；③ 把**可注入文本表**拷成"强制重编码"副本（只清 `text_zh` 列）⇒ 注入器用新 charset 重新编码写盘 |
| **会被重编码的文本** | `EN_STRINGS.RES`（**2 份副本**：MENU.IMG #25、GR.IMG #902）+ `EN_SPECIAL_FEATURE.XML`（**1 份**：MENU.IMG #283，且**只重写 `<text>` 元素**） |
| **不会被重编码的** | ★ **SFXML 的 `<item name="…">` / `<group name="…">` 属性**（中文标题就在这儿）；`<picname>/<moviename>/<soundname>/<3dname>`；两个 IMG 里其余条目；ISO 独立文件；ELF |

### 2.2 漏网容器 = SFXML 的 `name=` 属性（闭环复现）

`tools/iso_build/repack_leak_scan.py`：

```
SFXML: <text> 开标签 69 个 (成对 69, 非空 58 ⇒ 会被重编码)
       name 属性 145 个, 其中含中文 123 个 (★从来不会被重编码)
用"重排前 charset + round50 搬运表"复现: 123 个中文 name 属性里 113 个会变成别的字
   ★ 标题属性 fd a1 cd a6 a7 a5 cf a8 d0  '何为幽灵？'  →  '何为强知营'      ← 与实机所见逐字吻合
   a3 f6 a2 b3            '士兵'   → '声兵'
   a6 a7 a5 cf …           '幽灵行动®任务1' → '强知行动年任务1'
```

⇒ round50 那个「何为**强知营**」**完全复现**：标题字节没变，charset 变了 ⇒ 旧码位指到别人的字形上。
（round50 记录里"drawlog 给的是新码位"是把 drawlog 里的**字节对**当成了"新码位"；
那串字节 `fd a1 cd a6 a7 a5 cf a8 d0` 是**旧码位**，`A6A7` 在重排后的表里正是「强」。）

### 2.4 B5：`GR_ZH95` 是不是也有同样的错字？—— **是，而且它就是源头**

* `GR_ZH94` 与 `GR_ZH95` 的 SFXML `name` 属性**逐字节相同**（104/104），
  `T0063`（何为幽灵？）那一条也一样；
* 差别在 charset：GR_ZH95 用的是**重排后**的表 ⇒ 同一串字节在 GR_ZH95 上就解成 `何为幽灵；`、

### 2.6 B7：结论 —— **保持 `--no-font-repack`**

理由（诚实优先）：

1. **容量增益 = 0**（round49/50 实测：可用格 237 → 237；重排只是把 1039 个字搬了个家）；
2. **代价大**：1039 个字换码位 + 1512 条文本 ×2 容器重编码；
3. **有可见回归**（round50 实机：doc 页标题变 `何为强知营`）；
4. **漏网面不止标题**：`name=` 属性 145 个（含中文 123 个）全都不会被重编码 ——
   要安全开重排，**必须先**把"非 `<text>` 的中文字节串"也纳入重编码（方案见下），否则每开一次都会再坏一批。

**修法（已设计，本轮未实施 —— 因为增益为 0，按验收判据保持关闭）**：
重排改完 `pair_of` 之后，对 SFXML 里**非 `<text>` 的中文字节串**做一次"旧码位 → 新码位"**原位重映射**：
对偶↔对偶同为 2 字节、单字节码不动 ⇒ **长度不变**，可原地改写，不动容器大小、不动 IMG 条目表。
（本轮已用同款手法把**历史上已经坏掉的** 49 个标题修好了，见 §2.7 —— 说明这条路走得通。）
