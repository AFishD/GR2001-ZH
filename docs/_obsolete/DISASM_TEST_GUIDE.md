| **B 线**：症状**完全不变** | ✅ 与"gate 0xBA 下 0xB1/0xB5 属前导区间 ⇒ 该特判不可达"一致 ⇒ B 线的挂在**别处**，直接看 F3 |
| **B 线**：症状**改善/消失** | ★ 重大发现：说明 B 线文本里仍存在**孤立的** `0xB1/0xB5`（串尾或后随 `<0xA1`/`>=0xFF`）⇒ 需要重扫文本容器（`work\tools\migrate_legacy_audit.py --gate 0xBA --base-gate 0xB1`），把"每处 `0xB1..0xB9` 后面都跟着已登记 trail"这条旧判据改成**含串尾/边界情形**的更严判据 |
| 中文显示变差（个别字变成别的字/空白） | ⚠ 只有在 `0xB1/0xB5` 本来就是**正常汉字**时才可能发生；在 A 线它们本就是图标码 ⇒ 理论上不会。若发生，请记录**具体字符**，说明该盘有"`0xB1/0xB5` 被当作汉字用"的文本 |

所以它的读数最有信息量 —— 它在 B 线的结果直接判定用户事实 #4 是否成立。

### F2 · `$fp` ABI 加固（`--set fp`）

```
0x005659A4  0808669F -> 0808669E   j 0x00219A7C  →  j 0x00219A78
```

**改了什么**：拦截器结尾不再跳过 `0x219A78 sq $fp,144(sp)`，于是 DrawString 的
尾声 `0x219DC4 lq $fp,144(sp)` 恢复的是**正确的调用者 `$fp`**。

**预期效果**：**应当与未修盘逐像素、逐帧完全一致**（这是加固，不是修 bug）。
唯一的差别是消除一个已在静态上定位到的野指针受害者：

```
0x2BA548  pcpyld $fp,$v0,$zero     ; fp = [0x5E70D8]（字体管理器）
0x2BA5C0  pcpyld $a0,$fp,$zero     ; 拿 fp 当 this
0x2BA5E0  jal    0x219A70          ; 再调 DrawString
```

| 实测现象 | 判定 |
|---|---|
| 与未修盘**无差别** | ✅ 预期。保留为正式加固项（零风险） |
| **症状改善/消失** | ★ `0x2BA5C0` 那条"绕过 `0x2BA540`"的控制流确实存在（未达成项 U2 得证）⇒ 报告 §2.5 / #4 升级为根因，并请把该函数（`0x2B82F0`）的完整 CFG 交回 |
| 出现**新的**异常（文字错位/闪烁） | ⚠ 说明有调用者**故意**依赖"DrawString 之后 `$fp` 是垃圾"—— 这与 ABI 相悖，几乎不可能；若真出现，请回滚 F2 并把现象交回 |

### F3 · 顶点包复位闸门（`--set pkt`）★ 本轮的根因候选

```
0x0021A040  1060004C -> 00000000   beq $v1,$zero,+76 → nop   （主包 flush 尾）
0x0021A144  1060000B -> 00000000   beq $v1,$zero,+11 → nop   （副包 flush 尾）
```

**改了什么**：把"flush 之后是否复位顶点计数"从
**`fontmgr+0x48 != 0` 才复位** 改成**无条件复位**。

**为什么这是根因候选**（报告 §1.2 / #1）：

| 项 | 值 |
|---|---|
| 写入下标 | `count`（主包 `fontmgr+0x44` / 副包 `fontmgr+0x68`） |
| 容量哨兵 | `slti count,1280`（主包）/ `slti count,2`（副包） |
| 哨兵时机 | **写入并 `count++` 之后**（`0x219FB4` 之后才 `0x219FCC`） |
| 复位条件 | `0x21A040` / `0x21A144` 的 `lbe`+`beq`：**`fontmgr+0x48 == 0` ⇒ 不复位** |
| ⇒ 越界算式 | 只要有一次在 `count >= 容量` 时 `fontmgr+0x48 == 0`，此后每次 `AddOneWord` 都把顶点写到**下标 ≥ 容量** ⇒ **顶点缓冲越界写 ⇒ 相邻堆块头（dlmalloc）被改坏** |
| 与 gate | **无关**（两线逐字节相同）⇒ 是唯一能同时解释 A/B 两线的静态候选 |

| 实测现象 | 判定 |
|---|---|
| **A/B 两线都改善或消失** | ✅✅ 根因确认 ⇒ F3 进正式补丁；同时请做**回归**：连续长时间游玩、反复开关菜单/L1 界面/队伍选择，确认没有新的渲染缺失（flush 语义变化可能少/多送一帧顶点） |
| A 线改善、B 线不变 | ⚠ 说明 B 线的挂起另有其因 ⇒ 转 §5 第 2 步 |
| 两线都**不变** | ❌ 顶点包不是根因 ⇒ 转 §5 第 2 步（下一步：定位谁写 `fontmgr+0x48`，见 U3） |
| 出现**渲染撕裂/丢字/闪烁** | ⚠ flush 语义被改变了：说明 `fontmgr+0x48 == 0` 时"故意不复位"是有意的。**请立刻回滚 F3**，并把"何时该复位"的时序交回（这会把根因指向别处，见 §5） |

**风险提示（如实）**：F3 是全套候选里**唯一可能改变正常渲染语义**的一刀。
建议**单独一盘**测（不要与 F1/F2 混合），否则无法区分"改善来自根因"还是"改善来自副作用"。

## 3. 三个探针（不进现役盘；只在新建的探针目录里跑）

### P1 · 顶点计数与复位闸门时序（最强、不需要改代码）

在 PCSX2 调试器里对 `0x0021A048`（主包复位）与 `0x0021A14C`（副包复位）下**执行断点**，
并在 `0x219FCC`（主包哨兵）/ `0x21A0D0`（副包哨兵）处记录：

| 记录量 | 寄存器/内存 |
|---|---|
| 写入下标 | `[s0+0x44]`（主包）/ `[s0+0x68]`（副包） |
| 复位闸门 | `lbu [s0+0x48]` |
| 包缓冲基址/容量线索 | `[[s0+0x28]+0x00]`（虚表）、`[[s0+0x4C]+0x00]` |
| 全局 | `[0x637AF0]`（AddOneWord 里反复读的那个全局） |

**判据**：出现 `count >= 1280`（或 `>= 2`）**且** `[s0+0x48] == 0` **且**随后**没有**执行
`sw $zero, 68($s0)` ⇒ **#1 站点成立，越界写已发生**。

### P2 · 谁写 `fontmgr+0x48`（闭合 U3）

在 `0x0021A03C` / `0x0021A140` 的 `lbu $v1,72($s0)` 处下**读断点**（或写断点打在 `72($s0)`
所指地址上，一旦知道 `s0` 的值即可）。目标：拿到 `s0`（= 字体管理器地址）与写 `+0x48`
的函数，从而确定"**什么时候闸门是 0**"，进而确认越界窗口是否真的会出现。

### P3 · 槽位算式探针（判定 U1，★ 只在**新建探针盘**上做）

**背景**：报告 U1 —— `0x41708C`/`0x416FA0` 的 `mult` 之后没有 `mflo`，
字面读法（地址 = `(lead-0xA1) + (trail-0xA1) + 0xE0`）与本地化工具登记的公式
（`slot = (lead-0xA1)*94 + (trail-0xA1)`）矛盾，而 `docs\REPORT_atlas_artifact.md` §3
的实机取证支持后者。

**探针做法**：

1. 复制一张现役盘到新建探针目录（**不动现役盘**），跑
   `python work\builds\GR_DISASM\tools\dfix_apply.py --iso <探针盘> --out <探针盘2> --set probe-slot`
   （6 个字：`0x417084/0x417090/0x417094` 与 `0x416F98/0x416FA4/0x416FA8`）。
2. 进同一个含大量汉字的画面（建议任务简报页），与未修的探针盘**同帧截图对照**。

| 观察 | 判定 |
|---|---|
| 汉字**大面积变成别的字** | ⇒ 未修盘本来是对的（乘积确实生效）⇒ **U1 结论 = 我的字面读法有误**，`mult`/`addu` 那 4 个字必须以"寄存器分配层面"重新求解（下一步：用 Ghidra 反编译 `0x417050` 那段，看 `HI/LO` 的真实数据流） |
| 汉字**变得更正确/错位减少** | ⇒ 静态推导成立 ⇒ U1 结论 = 乘积确实被丢 ⇒ 把它升级为正式修复（但要先重跑全盘字形对照，因为它会改变**所有**对偶字的采样位置） |
| 完全无变化 | ⇒ 该 cave 在实机上**没被走到**（即 `a1 < count` 恒成立、UV 全部来自 20 字节记录表）⇒ 这本身是重大情报：**图标特判之外的"槽位"根本不是引擎算的，而是记录表给的**，请把这结论交回，我会重排站点优先级 |

### 8.1 ⛔ `probe-slot` 是**基于误读**的，禁止应用（原 P3 探针取消）

本文 §5 第 3 步与 `REPORT_DISASM_ROOTCAUSE.md §4 #3` 建议"跑 P3 探针盘（`--set probe-slot`）"。
**该建议作废**，理由是硬字节证据：

* `0x416FA0 = 0x012E4018` / `0x41708C = 0x018E6018` 不是 MIPS32 的两操作数 `mult`，
  而是 **R5900（EE 核）的三操作数 `MULT rd, rs, rt`**（SPECIAL `funct=0x18`，**低 32 位积直接写 `rd`**）。
  `0x012E4018` 的 `rd = (w>>11)&31 = 8 = $t0`、`rs = 9 = $t1`、`rt = 14 = $t6` ⇒ `$t0 = $t1 × 94`。
* 本工程既有反汇编器 `work\tools\cave_dis.py:94`
  `if fn == 0x18: return "mult $%s, $%s" % (r[rs], r[rt])` **丢掉了 `rd` 字段**，
  于是产生了"乘了却没人读"的假象。
* 写出侧就是三操作数：`tools\hanliu\tools\patch_db2_elf.py` 第 46 行 `mult3()` 用 `funct 0x18` +
  `rd` 生成它；`docs\FONTRES_STRUCTURE_r83.md` 第 119 行的注记**当年就写对了**。
* 同段代码里作者两种写法都会用（`0x4170B0 div $zero,$t4,$t6` 主动丢商 + `0x4170B4 mflo $t5` 取商），
  进一步证明 `funct 0x18` 不是"需要 `mflo`"的形态。

⇒ **`idx = 0xE0 + (lead−0xA1)×94 + (trail−0xA1)`，`slot = idx − 0xE0`；`×94` 一个字都没丢。**
⇒ 用 `dfix_apply.py --set probe-slot` 会把 `addu $t4,$t4,$t5` 换成读**上一次 `DIV` 的陈旧 `LO`** 的 `mflo`，
**把所有对偶汉字的槽位改错**。
**建议 Lead 在 `dfix_apply.py` 的 `PROBE_SLOT` 表与 `--list` 输出上加一行"作废（见 REPORT_LAYOUT_AUDIT §2）"。**
（本任务不动 `GR_DISASM` 任何文件。）
