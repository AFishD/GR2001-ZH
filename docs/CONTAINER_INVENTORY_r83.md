## 1. ★ 先更正 Lead 的前提：容器里**没有** 196 KB 别的纹理

`LEAD_RECORD_FORMAT_CONFIRMED.md` §二：
> 「图集 1024×512 @4bpp = **65,536 B**；像素容器 = 262,160 B = 8×32,768 ⇒ 约 196 KB 是别的纹理」

**这是把 4bpp 当 8bpp 算的（差 4 倍）**：

```
1024 × 512 @ 4bpp = 1024 × 512 / 2 = 262,144 B          （不是 /8 = 65,536）
容器 px_size = 262,160 B = 262,144 (纹理本体) + 16 (尾部 no-op GIFTAG)
实测: 8 段 × 48 B GIF 前缀 + 261,760 B 段数据 = 262,144  ✓ 分毫不差
引擎口径覆盖率 = 99.80%  (512 行里只有最末一行没铺满)
```

⇒ **容器 = 一张 1024×512 PSMT4 纹理，没有第二块纹理、没有可冻结/搬移的区域。**
⇒ 「从容器内部腾 ~196 KB」这条路**在算术上不存在**。
⇒ 能腾的只有**纹理内部没被任何采样窗覆盖的像素**（下面第 3 节的 98,600 texel）。

### 2.3 逐 texel 写入坐标（本轮的写盘器 `zx_r83_patch.Pix` 用的就是它）

```

```

## 3. ★ h=512 下的真实容量账（本轮的"能不能做 364 个"的答案）

### 3.1 已占用的采样窗（盘上实测）

```
对偶码格位: 现役 1504 个 = 1504 × 256 = 385,024 texel （行 0..24）
FT 记录采样窗: 544 条记录 → 208 个唯一矩形, 并集 40,664 texel = 158.8 个 16×16 格
   · 其中 16×16 矩形 111 个 · 8 宽(ASCII) 矩形 92 个 · 其它 5 个
并集 = 425,688 texel  ⇒ 自由 = 98,600 texel = 385.2 个 16×16 格
贪心铺放实测: 自由区里**最多还能放 229 个 16×16 字形**
```

### 3.2 码位空间（比像素空间更紧的瓶颈）

```
引擎可寻址的码位 = 对偶槽 + 单字节码
  对偶槽  : slot = (lead−0xA1)·94 + (trail−0xA1),  lead ∈ [0xA1, gate)
            gate = 0xB1 ⇒ 16 leads ⇒ 1504 槽（**现役已全满**）
            网格公式 row = slot/62 ⇒ **y = 2 + 16·(row + 3 if row≥12)** ⇒ 行 0..27（y 2..497）
            ⇒ h=512 时**最多 28 行 × 62 列 = 1736 槽**（行 28 ⇒ y=498..513 **越界**）
  单字节码: 0x00..0xA0 ∪ [gate, 0xFF]；现役用掉 0x20..0x7E(ASCII 95) + 0x80..0xA0(33) + 0xB6..0xFF(74) + 图标
            gate=0xB1 ⇒ 可用 208；**空闲只剩 0x7F / 0xB2 / 0xB3 / 0xB4 = 4 个**

容量（gate, NCOL=62）:
  gate=0xB1: 1504 槽 + 208 码 = 1712   ← 现役 1504+202=1706 ⇒ **只多 6 个**
  gate=0xB4: 1786 槽（可寻址 1736）+ 205 码 ⇒ 总 1941 ⇒ **多 235**
  gate=0xB5: 1880 槽（可寻址 1736）+ 204 码 ⇒ 总 1940 ⇒ **多 234**
⇒ ⇒ **364 个缺字在 h=512 + 现役布局下放不下**：上限约 **232 对偶槽 + 1 单字节 = 233 个**。
```

### 3.3 本轮实际采用的布局（把"能拿的都拿到"）

```
· 网格可寻址槽 0..1735（行 0..27）；**现役 1504 个（行 0..24）一格不动**
· 新字放槽 1504..1735 = **232 个**：
    行 24 尾 col 16..61（y 434..449）**本来就空** → 32 格
    行 25/26/27 全行（y 450..497）→ 186 格 ★ 与两条活带冲突，必须搬带
· 两条活带搬家（像素逐 texel 搬运 + FONT.RES 里 332 条记录改矩形）：
    (452,468) EN 带 92 个唯一矩形 8×16  ·  (482,498) KB 带 28 个唯一矩形 16×16
    → 在自由区贪心重排；搬完剩余自由 39,208 texel = 153.2 格（余量充足 ✓）
· 单字节码再拿 0x7F 一个（本轮未做，见报告"未完成项"）
```

### 3.4 静态容量上限的几何证明（写给下一轮）

```
图集 = 2048 个 16×16 格
  · 对偶槽必须落在 (16·col, 2+16·row') 上，col<62（或改 cave 到 64），row'≤30
      ⇒ 28 行 × 62 = 1736（改 cave 的 gap 3→0 可到 31 行 × 62 = 1922）
  · 记录窗可落任意位置（记录矩形 = 采样矩形，见 R83-A §2.4）
⇒ 想装 1504 现役 + 364 新 = 1868 个，必须**改 cave 的 gap 并整体重铺图集**：
     gap 3→0（1 条 `addiu` 立即数） ⇒ 31 行 ⇒ 1922 槽
     但行 12..24 的 744 个现役字形要整体上移 48 px，且 y194..241 的记录带要让位
     像素账: 1868×256 + ASCII 95×128 + 单字节 107×256 = 517,760 ≤ 524,288（余 6,528）
     ★ 余量只有 2.5%，且记录只能落进 118 个非网格格 ⇒ **风险高，须单独一轮做**
```
