## 2. 字形管线: 现有 1175 个字形是怎么来的 (先摸清, 再沿用)

### 2.1 结论先行: **可用**

字形来源是**第三方点阵字体**, 不是从原盘抠的:

| 环节 | 位置 | 事实 |
|---|---|---|
| 字形源 | `third_party/fonts/方正像素16.ttf` | 2,632,936 B, 存在且可读 |
| 渲染配方 | `tools/font_pipeline/gen_font16.py::render16()` (L147–163) | PIL `truetype(16)`, 32×32 白底, `draw.text((8,8))`, 取 **canvas[8:24, 8:24]**, 阈值 **<128** ⇒ 16×16 布尔墨窗 |
| 布局常量 | 同文件 L64–70 | `NCOL=62, CW=CH=16, Y0=2, SKIP_ROW=12, SKIP_ROWS=3`; 行窗 `y(r)=2+16r+48·[r≥12]` |
| 编码→格 公式 | ELF cctc cave (反汇编, 见 `tcslib.atlas_cell_xy_engine_view`) | `slot=(lead-0xA1)*94+(trail-0xA1)`; `row=slot//62, col=slot%62`; 引擎格左上 = **(16·col, yrow(row))**, **无相位** |
| 图集容器 | `COMMON.PAK` 记录 `new_font_revised` | PSMT4 1024×512, `px_size=0x40010`, texel **0 = 墨** / **1 = 透明底**; 字节流是 **GIF 封包流**(9 段 × 48 B 包头) |
| 同一配方的独立实现 | `tools/iso_build/single_cell_font.py::Templates.get()` (L237–250); `tools/iso_build/glyph_geometry.py::Templates` | 三份实现逐字同款 ⇒ 可以用后者做**逐像素**验收 |

`charset_compiled_zh16.json` 由 `gen_font16.py` 写出的 `charset_compiled_v16.json` 演化而来
(`pair_of` / `codes` 两个字典 + 各轮补丁追加的 `_*` 说明节), **本轮只往 `pair_of` 追加 329 条**。

### 2.2 本轮为什么**不**重跑 `gen_font16.py`

`gen_font16.py` 会**整张重建**图集(全部 1136+76 字重画)、重建 FT 表、重建 `COMMON.PAK`
—— 与「只增不改, 不动现有 1175 个格与其 FT 记录」的硬约束直接冲突。
所以本轮只**复用它的 `render16` 配方**渲染 329 个新字, 逐格写进空位;
`tools/iso_build/patch_zh113_expand_font.py` 里那份 `render16` 是**逐行同款**的副本,
并由 `single_cell_font.py`(第三份独立实现)在验收时逐像素反证(§5⑤/§5-A2)。

### 2.3 渲染可行率实测 (`r2_select.py`)

693 个候选逐字跑同一配方:

| 判定 | 个数 | 说明 |
|---|---|---|
| `ok` | **692** | 16×16 em 窗内有墨、墨不越窗 |
| `ttf_missing` | **1** | `嘚 U+561A` —— 方正像素16 里没有这个字形 |
| `overflow` / `zombie` | 0 / 0 | —— |

⇒ 管线**完全够用**(692 ≫ 329)。

## 3. 选字依据 (为什么是这 329 个)

### 3.1 候选池

= 用户**丰富版**文本(`work/builds/GR_ZH109/text_backup_before_wrapfix/` 那份)里

(现役 `GR_ZH111/text/` 是缩减版、0 缺字, **不是**本轮候选来源。)

### 3.2 排序与拒收规则 (可复跑、确定性)

1. 排序 = **出现次数降序**, 同频按 **码位升序**(⇒ 同一份输入永远选出同一份清单);
2. 逐字跑 §2.1 配方, 三类**拒收**: `ttf_missing`(TTF 无此字形)、`overflow`(墨越 16×16 em 窗)、
   `zombie`(<128 阈值下渲染为空);
3. 取**前 329 个通过检验**的, 按顺序填 slot 1175 → 1503 (**高频 → 低 slot**)。

## 9. 已知限制

1. ★ **新字只在 lead ≤ `0xB0` 有效, 超出即失效。** 引擎的 lead 判据是 ELF 4 处
   `sltiu reg,0xB1`(0x416EE8 / 0x417160 / 0x41751C / 0x5656A4), 即 `0xA1 ≤ b < 0xB1`;
   `0xB1` 及以上**不是 lead**, 会被当**单字节**拆成两个字形(round65 实拍: 6 个字渲染成 12 块,
   行宽 27 px → 114 px)。所以**这次的 1504 就是当前 ELF 的硬上限** ——
   再想加字必须改 ELF gate(= 换一套 `方案 C` 参数 + 重测), 或者回收现有字形。
2. **`0xAF` / `0xB0` 这两个字节现在被"占用"为 lead 了。** 它们原本是空字节(不是图标码),
   现在作为对偶 lead 使用 ⇒ 文本里**不能再**把它们当单字节码写(会吞掉后一个字)。
   `dump_font` 的"空字节"清单已从 `B1 B5 AF B0` 变成 `B1 B5`。
3. **图集已满**: 对偶格占用 1504/1504 = 100%, `font_cell_map` 的可用格 = 0,
   可回收墨 = 0 ⇒ **这一张 1024×512 贴图再也放不下新字**了。下一步只有:
