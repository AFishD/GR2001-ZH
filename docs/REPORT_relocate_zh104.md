## 一、现象：88 个对偶格被「别人的字形」占着

`tools/iso_build/font_cell_map.py` 把 1504 个对偶槽位逐个分类（GR_ZH103 实测）：

```
对偶槽位 1504 = 在用 1175 + **可用(空白且不被记录压) 234** + 空白但被记录压 7
               + **被活字形占着 88** + 可回收 0 + 死pair 0 + 不可寻址 0
```

那 88 个格子**不是空白**：格里的墨归 **84 条 FT 记录**所有 ——

| 记录 | 条数 | 记录矩形尺寸 | 每条压几格 |
|---|---|---|---|
| 单字节汉字 | 80 | 16×16（正好等于一个对偶格） | 1 |
| 滚动箭头 `0x7B` `0x7D` | 2 | 5×13 | 2 |
| `ç 0xE7` `ñ 0xF1` | 2 | 7×13 | 2 |

实测（`work/builds/GR_ZH98/temp/r54/recon.py`）：

- 88 个格**每个只被恰好 1 条记录覆盖**（多重覆盖 0 个）⇒ 整条搬得动，不会撕开别人的字形；
- 84 条记录在 3 个 face 里的矩形**逐条相同**（`large` / `default` 完全一致；`huge` 只有 96 条记录，
  码位 ≥ 0x80 本来就不在它的范围里）⇒ 3 个 face 同步改指同一个新矩形即可。

**后果**：这 88 个格当不成可用格 ⇒ 想写新字只能挤在 234 个空位里。

## 二、思路：把字形搬到「引擎永不采样的地方」，显示不会有任何变化

### 2.1 引擎怎么用 FT 记录（关键依据）

反汇编证据（`docs/han_v2/PS2_FONT_MECHANISM.md` §2.2 / §3，本仓库既有结论）：

```
ComputeCharTextureCoords(0x21ADE0):  *u0 = rec.u0 >> 1 ; *v0 = rec.v0 >> 1 ; ...
    ⇒ u0/v0/u1/v1 **原样**当纹理坐标，没有任何"按格重排/对齐"
DrawString(0x219A70) 字形四边形:   pos = {x0 = x, y0 = y, x1 = x + advance×scaleX,
                                          y1 = y + CharHeight×scaleY}
    ⇒ 屏幕上的大小 = **advance × 字面高**，与记录矩形的绝对位置**无关**
```

⇒ **记录矩形在图集里的位置只决定"采样哪一块 texel"，不决定画在哪、画多大。**
旁证（本工程自己的观测）：对偶字形分布在同一张图集的 25 个不同 y 行（y=2 … y=450），
但它们都画在同一条基线上 —— 引擎不可能把 `v0/v1` 的绝对值当屏幕位置用。

再一条**实机**旁证（round45）：当时清理记录带时误把 `0x7B`/`0x7D` 的像素擦掉，
实机表现为「详情页上下滚动箭头变暗」（见 `tools/iso_build/patch_zh94_glyph_align.py` 注释与
`docs/REPORT_glyph_align.md`）⇒ 连引擎"特制"的滚动箭头也是**按记录矩形到图集上采样**的，
所以把这块像素**等尺寸搬走 + 记录改指**，画出来的东西不变。
（唯一的例外是 `0xB1`/`0xB5` 手柄图标码 —— 它们的 UV 硬编码在 `DrawString` 里、不吃字库；
本补丁**没有**动它们，它们也不在这 84 条里。）

因此：**把旧矩形的像素原样写到新矩形、把记录指过去、`advance` 不动** ——
引擎采到的还是同一张位图，画出来的四边形一模一样 ⇒ 显示逐像素不变，而原来的格子就空出来了。

### 2.2 落点：对偶网格之外的空区

对偶网格 25 行之间有一段**引擎永远不采样**的空隙：

```
网格行 11 : y = 178..193        ← 这一段被 80 个单字节汉字占着（本补丁要腾空的）
空区      : y = 194..241        ← 墨 0 px、3 个 face 里没有任何记录矩形、192 个干净 16×16 格
网格行 12 : y = 242..257        ← 被跳过的 3 行就在这里（GRID_SKIP_ROWS=3）
```

⚠ **y=194 这一行不能用**：`atlas_cell_xy_engine_view` 对**回绕列**会给 `y+1`
⇒ 网格行 11 的 16 个回绕格（x=0,16,…,240）覆盖 **y=179..194**，y=194 属于**在用对偶格**。
本补丁把 84 条全部放进

```
带 A: y = 195..210    带 B: y = 211..226      （x = 16k, k = 0,1,2,…）
```

（仍在要求的 `y=194..241` 内，但天然躲开 y=194 与 y=242 两条边界。）
