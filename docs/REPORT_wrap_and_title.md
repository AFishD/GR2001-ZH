## 1. 折行引擎全貌（现象 A）

### 1.1 谁在折行

`RSHTML`（继承 `RSTextComponent`）持有介绍框：

* `RSHTML::CreateStrings @0x21B890` 先按 **`{br}` / `{p}` 标记把文本拆成"段"**，对**每一段各调一次**
  `RSTextComponent::DoWordWrap @0x21CC10`；`{p}` 额外压入一个空行。
* 折行结果 = `comp[0xAC]` 的**断点数组**（首项恒 0，末项恒 `Length(text)`），行数 = 数组长度 − 1；
  再由 `RSHTML` 转成 `RSArray<RSUIString>`（`comp+0x110`）的实体行。
* `RSHTML::DrawHTML @0x21BC80` 按 `comp[0xFC]`（滚动起点）逐行调
  `RSTextComponent::DrawOneLine @0x21C8B0`，每行 `y = comp[0xEC]`，行末 `comp[0xF4] += comp[0xF8]`。

**武器介绍框实测（EE RAM，帧 11030）**：`COMP=0x12F4960`
`W=comp[0x40]=270`、`comp[0xB4]=0`、`H=comp[0x44]=190`、`lineH=comp[0xF8]=18`、
`ax=35`、`ay=173`、`font=comp[0x98]=0x6892B0`（= fonts[0]）、`comp[0x1C]=0x20000`（可滚动）。
⇒ **wrapW = 270**（`0x21CC90: subu $s7,$v1,$v0`）。

### 1.2 宽度模型（全部从 live EE RAM 取，不靠猜）

`RSFont::StringWidth @0x21AC00`：`SW(s) = Σ CharWidth(字) + (字数 − 1) × font[0x18]`
`CharWidth @0x21AD10 → cave 0x416F40`：`宽 = fptosi(font[0x1C] × 字宽表[记录].byte1)`，DBCS 越界时**恒 16**。

| 类别 | 值 | 来源 |
|---|---|---|
| 汉字（双字节 0xA1xx–0xADxx） | **16** | cave `0x416FBC` 硬编码 16 |
| 汉字（单字节码 0xAF–0xFE，76 个高频字） | **16** | 字宽表 idx 143..222 |
| ASCII 0x21–0x7E | 8 | 字宽表 |
| `{` `}` | 5 | 字宽表 |
| 空格 0x20 | `font[0x14]` = **3** | fonts[0] |
| 0xB1 / 0xB5（protected） | 20 | cave |
| 未用码 0x7F–0xAE | 10 | 字宽表 |
| tracking `font[0x18]` | **1** | fonts[0] |
| 缩放 `font[0x1C]` | 1.0 | fonts[0] |

> 复核"15 汉字/行"：逐字循环条件是 `Σ(字宽+tracking) < wrapW`：
> `15×(16+1)=255 < 270`，`16×17=272 ≥ 270` ⇒ **正好 15 个全角字**；
> 余量 15 单位还能再放 1 个 ASCII（9）。**与"标点也算全角"一致**（`，。、` 都是 16 宽双字节码）。

### 1.3 贪心规则（首行浪费的确切机制）

`DoWordWrap` 主干（已逐字核对反汇编）：

```
budget = wrapW = comp[0x40] − comp[0xB4]
for 每个空白切分的 token T:
    w = StringWidth(T)
    if w > wrapW:                    → 进"硬断"分支（见 1.4）
    budget −= (w + 行开销)            # 行开销 ≈ 空格 fp + tracking
    if budget < 0:
        记录断点 = 当前 token 的**起始字节偏移**
        budget = wrapW − w + fp       # 新行预算 = 整行 − 引起换行的这个 token
```

* **断点记在"装不进的那个 token 的开头"**，而不是"尽量往前塞"。
* 因此**首行只放一个短词**的充要条件是：
  `cost(首 token) + cost(第 2 个 token) + 行开销 > 270`。
* 这**与"第 2 个 token 是否超宽"无关**——它比一行窄得多也照样被推到下一行。

**M18（ZH84 现文本）逐字算术**

```
T1='M18'                       SW = 3×8 + 2×1        = 26
T2='定向反步兵地雷由曲面的方形硬'   SW = 14×16 + 13×1     = 237
首行预算 270 → 减去 T1(26) 与 tracking(1)、空格(3+1) ⇒ 余 239
239 < 237 + 4(空格fp) + 1 ⇒ 断在 T2 开头 ⇒ 首行 = 'M18 '  = 31/270 = 11%
```

**M2（对照：首行铺满）**

```
T2='定向炸药是一种定向装药，'      SW = 13×17 = 221
239 ≥ 221 + 5 ⇒ T2 进首行；再下一个 token 才装不下
⇒ 首行 = 'M2 定向炸药是一种定向装药，' = 230/270 = 85%
```

⇒ 用户看到的"M18 只剩一个词 / M2 铺满一行"是**同一个算法在两段文本上的正常输出**，差别只在
"第 2 个 token 是 14 字(237) 还是 13 字(221)"。

> **本盘与 EN 的一处差异（折行相关，需知晓）**：`0x21CECC` 在本盘是 `nop`
> （EN 为 `addiu $v0,$v0,1`；PATCH_INVENTORY 记为本工程 V13W 轮"wrap 配套"补丁）。
> 于是"token 末尾 +1 跳空格"改由 follow-up 的 skip 循环吸收（该循环还会 `budget −= fp`）。
> 这是"硬断续行不再逐行错位 1 字节"的原因，上面的模型已按现状实现。

### 1.4 硬断分支（词被劈开的来源）

`0x21CD28`：仅当**单个 token 的 `StringWidth > wrapW`** 时进入。
其后按**逐字累加 `Σ(字宽+tracking) < 270`** 切片 ⇒ 每片恰好 15 全角字，
**切点不看任何语义**（标点可落下一行行首、词可被劈开）。

**两组实测真值（用于回归）**

| 真值 | 数据 |

| ZH82 奖章 `{p}` 段（无空格） | `15,15,15,15,15,6` 字（`。`/`，` 落行首） |
| ZH84（插空格）M18 | 9 行，首行 `'M18 '` |

## 3. 现象 A：可执行的插空格规则

### 3.1 规则（用一行容量与实测标定，不含拍脑袋常数）

```
cost(s)   = Σ 字宽 + 字数×1      # 汉字16, ASCII8, 空格3, {B1,B5}20
CAP_LINE  = 255                  # 无编号行: 15 汉字 (255 = 15×17 < 270)
CAP_FIRST(D) = 260 − cost(D)     # 段首短编号 D 之后首行内容上限 (二分标定, 误差 0)
                                   #   D='M18'(27) → 233 (=13 汉字)
                                   #   D='M96A1'(45) → 215 (=12 汉字)
                                   #   D='Tom Clancy'(85) → 175 (=10 汉字)

for 每个 {br}/{p} 段 (各自独立, 引擎按段折行):
    D = 段首 token, 若含 [0-9A-Za-z] 且 cost(D) ≤ 60
    rest = 其余文本 (原有空格保留, 只增不删)
    first = True
    while rest:
        cap = CAP_FIRST(D) if (first and D) else CAP_LINE
        n = "cost(rest[:n]) ≤ cap 的最长前缀"
        n = 回退, 直到 rest[n] 不是收尾标点(。，、；：！？）》”…)
        n = 在 [0.85·cap, cap] 窗口内优先取:  rest[n-1] 是标点  或  ASCII 词边界
        输出 rest[:n] 作一行;  rest = rest[n:] (跳过起始空格);  first = False
    在每两个相邻"行"之间插入 0x20
```

**关键点**

1. **每个无空格串 cost ≤ 255** ⇒ 永不进硬断分支 ⇒ 不会劈词、标点不会掉到行首（规则 R2 双保险）。
2. **段首编号与后续内容共占首行**（`CAP_FIRST(D)`）⇒ 消灭"M18 独占一行"。
3. 断点优先级：标点后 > ASCII 词/数字边界 > 按 cap 断（要求填到 85% 才接受更早的语义边界，
   避免"为了标点把行填成 60%"）。
4. `{br}`/`{p}` 段各自独立满足容量约束（引擎对每段重置预算）。

## 4. 现象 B：栏目标题下沉

### 4.1 有**两条**绘制路径，都不是 `ComputeDrawXY` 的居中分支

| 对象 | 绘制函数 | y 公式 | 与 EN 差 |
|---|---|---|---|

| 内页顶部大标题（`武器`/`奖章`…，左上角） | **`RSTextComponent::DrawTheString @0x21C4C0`**（drawlog `RA=21C62C`） | `ay + comp[0x4C]`，再由 zh7 cave 加 **+7** | **+7 px（偏低）** |

### 4.3 为什么上一轮 `0x4176A0` 字高 16→20 的补偿没生效

* **金框标题根本不走 `RSTextComponent::ComputeDrawXY`**，而是 `IkeBaseButton::DrawText` 自己的
  `(H − K)/2` 分支（风格门 = `comp[0x1C] = 0x0100000F` ⇒ `StyleIsSet(0xC)` 真）。
  `0x4176A0`（假 CharHeight）**在这条路径上没有任何调用点**。
* **内页大标题虽然走 `ComputeDrawXY`，但进不了居中分支**：
  `COMP=0x12F3080` 实测 `comp[0x1C]=1` ⇒ `StyleIsSet(3)`、`StyleIsSet(0xC)`、`StyleIsSet(8)`
  全为假（`StyleIsSet @0x50DAD0` 对 3/2/1 用 `&3 == n`，对 4/8/0xC 用 `&0xC == n`）。
  它只走 `0x21CA50` 的 cave（`y = comp[0x3C]+comp[0x4C]`，`style&0xFF==0x52` 才 +4；本件 style=0x53 ⇒ 不加），
  加 0，`comp[0x108]` 低字节为 0（不跳过居中但也没居中可做）。⇒ `0x4176A0` 永不执行。

### 4.4 具体修法（地址 + 常数）

**B-1 金框标题（+3 px，全部栏目行 + 内页条目名）**

```
文件: ELF @LBA295
0x21D940  现值 0x2462FFEB  = addiu $v0,$v1,0xFFEB   (H − 21)
  改为    0x2462FFE6  = addiu $v0,$v1,0xFFE6        (H − 26)      → 上移 3 px = EN
  或还原EN 0x00621023  = subu  $v0,$v1,$v0           (= H − CharHeight(font))
```
* `CharHeight(font)` 现值 = `desc[0xC]` = **26**（EE RAM 实测，与 EN 同值）⇒ 上面两种改法等效。
* 目视校验：金框内部（文件像素 y=77..96）、墨迹 y=82..96（上留白 5 / 下留白 0）。
  上移 3 game px（≈2.9 文件 px）后约 y=79..93 ⇒ 上/下留白 **2 / 3 px**，既视觉居中又与 EN 对齐。
* 影响面：所有走 style-0xC 的按钮族（SF 金框 10 行、内页条目名、以及
  `0x21D940` 原有的训练标题/文件槽等）。改后它们统一回到 EN 关系，需做一轮菜单回归。
* 现役 10 个金框行组件（EE RAM 实测，模板完全一致）
  `W=236 H=31 ax=72 comp[0x1C]=0x0100000F comp[0xD9]=3`，`ay=76,106,136,166,196,226,256,286,316,346`
  ⇒ **影片/设定图/音乐/武器/奖章/背景/屏幕截图/访谈/预告片 + 未解锁空白行，同一路径同一问题。**

**B-2 内页顶部大标题（+7 px）**

```
0x565910  现值 0x24E70007 = addiu $a3,$a3,7      → 改为 0x00000000 (nop)  ⇒ 上移 7 px = EN
（cave 0x565900 是 zh7 绘层改道的"伪 RA"尾跳钩子, 由 0x21C624 的 `j 0x565900` 进入;
  其门 = 0x565904 `addiu $t4,$zero,5` 与 0x565900 `lbu $at,0x9C($s1)`）
```
* 备选（更保守）：把 `0x565904` 的门槛值改成没有组件取到的值（如 `-1`），只关掉这个 +7；
* 更保守的**数据侧**做法：把该标题组件资源里的 `comp[0x4C]` 由 0 改成 `-7`（0xFFFFFFF9），
  只影响这一个实例，零 ELF 风险（需在 UI 记录里定位该组件）。
* 影响面：所有 `comp[0x9C]==5` 且走 `DrawTheString` ≤2 行路径的文本（即"页面大标题族"，
