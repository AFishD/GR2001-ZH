## 0. 一句话结论（★ 推翻上一轮）

**「像素容器变大 ⇒ 读盘停摆」不是引擎的尺寸阈值，而是构筑不变式被违反。**
把 ① `real`、② `px_size` 两条修对之后，**图集从 512 行长到 644 行（容器 +67,584 B = +25.8%）完全通过**
—— 读流跑到 LBA 804,765 / frame 5860，191 张截图里 **182 张与对照盘逐字节相同**。

```
闸门 ①  real 不变式:  引擎对 IMG 条目的**读流长度 = min(stored, real)**。
        历史所有"容器变大"探针盘（GR_TEST_W2048 / GR_ROOT85_gate /
        GR_TEST_FONTCAP_H640/H640B/H1024 / GR_ZH121 …）都**只改 stored(+0x18)、
        没改 real(+0x1C)** ⇒ 读流在 PAK+real(旧值 400,659) 处截断 ⇒
        `LoadingTexturePak`(0x51B660) 记录链读到流尾后**死循环** ⇒ 0 截图 /
        读流 frame 0..257 停死 / newfontrevisedrs 从未进内存。
        ★ 与"容器变大"无关: 只把 real 补上(同样一张盘、2 个字节), 立刻恢复。

闸门 ②  px_size 不变式: `px_size == w*h/2 + 16`，且 nseg×48 的段头**从像素区里挤出**
        （payload = w*h/2 − nseg×48）。等价可判式: **(w*h/2) % 2048 == 0**。
        违反 ⇒ 卡在"正在读取插槽 1 中的记忆卡 (8MB)"画面（191 张同一画面）。

闸门 ③  容量上限（本轮新发现）: **px_size ≤ 329,744 通过（h=644）/ ≥ 344,080 失败（h=672）**
        ⇒ w=1024 时 h_max ∈ [644, 668] 且 h ≡ 0 (mod 4)。超过 ⇒ 同上卡记忆卡画面。

闸门 ④  引擎静态尺寸闸门（`UITexture::LoadPS2Img`）:
        w<1025 ∧ h<1025 ∧ clut<1041 ∧ px_size<0x100001。
        ⇒ w=2048 实测 ✗（w>1024 撞 0x51D9BC 硬闸），**w 方向不可走**。
```

**对"364 缺字"的答案**：走 h 方向，**推荐 h=640（Δ=+65,536 B，实机 ✓，ISO 一字不必加长）**。
需要 8 行新格；h=640 给 128 行 × 62 格 = **7,936 格** ≫ 364；最小已证 h=516/520（496 格）也够。

  ⇒ **"主循环跑满 6000 帧"完全不能作为"没卡"的证据。**
```

## 5. 能否绕开？—— **不需要任何代码补丁；这是纯数据构筑问题**

### 5.1 精确配方（基底 `work\builds\GR_ZH124\GR_ZH124.iso`，MENU_LBA = 776,286）

```
设 w=1024（不动）, h=新高度（h ≡ 0 (mod 4), 512 ≤ h ≤ 640 推荐）,
   nseg = ceil(h/64), Δ = (1024*h/2 + 16) − 262,160

① 记录字段（COMMON.PAK = IMG 条目 #3, off=0x57400）:
     h        ISO 0x5EC87451 (= PAK+0x1051)  原 00 02 00 00  →  h 小端 u32
     px_size  ISO 0x5EC87869 (= PAK+0x1469)  原 10 00 04 00  →  (1024*h/2 + 16) 小端
     w        ISO 0x5EC8744D                 原 00 04 00 00  →  **不动**
② 容器（ISO 0x5EC8786D 起, 长 = 1024*h/2 + 16）:
     每段 = [PT GIFTAG(REGS=A+D, PACKED, NREG=1, NLOOP=1, EOP=0)]
            [A+D 16 B: SSAX u32=0, SSAY u32=64k, u64@+8 = 0x52]
            [IMAGE GIFTAG: u32@+0 = (len/16 | 0x8000), u32@+4 = 0x08000000]  (FLG=2, EOP=1)
            [len 字节像素]
     段 0..nseg−2 各 0x8000 B；末段 = (1024*h/2 − nseg*48) − (nseg−1)*0x8000 B
     末尾 16 B no-op: 00 80 00 00 00 00 00 08 00 00 00 00 00 00 00 00
     ⇒ 旧 512 行像素逐字节保留在每行开头（x<1024），新区域填 0x11
③ 条目表（MENU+0x830 + 48*idx）:
     COMMON.PAK stored  MENU+0x8D8 (ISO 0x5EC2F8D8)  原 400,659 → 400,659+Δ
     COMMON.PAK real    MENU+0x8DC (ISO 0x5EC2F8DC)  原 400,659 → 400,659+Δ   ★★ 必须同步
     682 条 off (off ≥ FONT.RES off 0xB9120)  MENU+0x830+48i+32 → 各 +Δ
④ MENU.IMG 声明长度 = max(旧值, last_end+Δ)（需要时取扇区对齐）；ISO9660 目录记录
   (@0x828D8 小端 / @0x828DC 大端) 同步；**只有 new_size 超出卷长时才动 PVD 卷长并加长 ISO**。
   h ≤ 640 时 Δ ≤ 65,536 < 89,908 B 空位 ⇒ **ISO 一字不加**；h=644/672+ 需 +82..85 扇区。
⑤ 不动: w / psm / clut+调色板 1040 B / 记录名字 / 记录条数 / FONT.RES / ELF / charset /
   文本 / 名字区 / **IMG +0x20 的 4096 槽哈希表** / 记录链 0x63 哨兵。
