## 2. 显示逻辑解析（哪个函数 / 哪个分支 / 门是什么）

### 2.1 路径 A：内页大标题（`0x565900` cave，**不是本次的病灶**）

```
0x21C624  jal 0x219EB0 (DrawString)  →  j 0x565900          ← ZH61 挂点 (现役 08159640)
0x565900  lbu $at,0x9C($s1) ; fontID
0x565904  addiu $t4,$zero,5
0x565908  bne $at,$t4,+2
0x565910  addiu $a3,$a3,7    ← 用户认证的标题居中量 (现役 24E70007, 本轮未动)
0x565918.. jr 0x219EB0 (伪 RA = 0x21C62C)
```
- 该路径 **只在 `RSTextComponent::DrawTheString` 内部**（`jal` 在 `0x21C624`）生效；
- 本轮实测：`武器` 的 pen y 在「现役 / 补丁盘」两盘完全一致（25），补丁**没有**触碰它；
- 墨迹实测：EN `Weapons` y[24.5..48.1]（26px 字）vs ZH「武器」y[25.5..38.9]（16px 字）⇒ 顶缘仅差 1.0px，**这一族没有可复现的「下沉」**（详见 §6）。

### 2.2 路径 B：金框条目条（**真正的病灶**）

`IkeBaseButton::DrawText @0x21D830`（反汇编逐词核对，`$s2 = 按钮组件`）：

```
0x21D860  $s0 = comp[0x38](ax) + comp[0x48]
0x21D868  $s1 = comp[0x3C](ay) + comp[0x4C]
0x21D898  StyleIsSet(0xC) 命中 → 0x21D934:
0x21D934  jal 0x21ACD0            ; CharHeight(font = comp[0x100]) → $v0
0x21D93C  lw  $v1, 0x44($s2)      ; H
0x21D940  K 常量:  EN 00621023 subu $v0,$v1,$v0   (K = CharHeight = 26)
                   ZH40 起 2462FFEB addiu $v0,$v1,-21 (K = 21, 硬编码)
0x21D944  bgez $v0,0x21D954 ; 0x21D948 sra $v1,$v0,1 (延迟槽) ; 0x21D94C addiu $v0,$v0,1 ; 0x21D950 sra
0x21D954  $v1 = (H − K)/2   ⇒  $s1 += comp[0xD9] + $v1     ; C 式向零取整
0x21D9E4  虚调用: 用 $s0/$s1 画按钮底/图标
0x21DA20  jal 0x219EB0 画文字 (drawlog 里 RA=21DA28)
```

**组件现场（EE RAM 实测，帧 F11300，`work/_dis/r27_scancomp.py` + 指针链回溯）**

| 用途 | comp | vtable | style[0x14] | sw[0x1C] | ax | ay | W | H | D9 | font[0x100] |
|---|---|---|---|---|---|---|---|---|---|---|
| **SF 内页条目条（病灶）** | `0x012F3510` | `00595520` | 0x1F | 0x0000000F | 20 | 80 | **600** | **20** | **10** | `00689334` |
| 前端列表行（主菜单 战术演习） | `0x0132FF60` | `00595520` | 0x1F | 0x0100000F | 43 | 154 | 284 | 31 | 3 | `00689334` |
| 特别收录列表行（影片/武器/…） | `0x012F3300` | `00595520` | 0x1B | 0x0100000F | 72 | 106 | 236 | 31 | 3 | `00689334` |

⇒ **同一个 (H−K)/2 旋钮管两类场景**：

```
条目条:  y = 80 + 0 + 10 + (20 − K)/2  →  K=21: +0 ⇒ 90 (现役)   |  K=26: −3 ⇒ 87 (EN 原盘同值)
列表行:  y = 154 + 0 + 3 + (31 − K)/2  →  K=21: +5 ⇒ 162 (用户认可) |  K=26: +2 ⇒ 159 (上移 3px)
```
> 取整是 C 式：`(20−21) = −1 → +1 = 0 → 0`；`(20−26) = −6 → +5 → sra = −3`。EN 原盘 `Claymore (M18 Claymore)` 的 pen 实测就是 **87**，与本式 K=26 完全一致。

### 2.3 「不是 `0x565910`」的实证

1. **调用点不同**：条目名的 DrawString 调用在 `0x21DA20`（drawlog `RA=21DA28`），而 cave 挂在 `0x21C624`（DrawTheString 内部）。`RA` 是"谁调用 DrawString"的返回地址，`21DA28` 说明它根本没经过 DrawTheString；
2. **行为实证**：本轮 K=26 诊断盘（`0x565910` 保持 `24E70007` 不动、只改 `0x21D940`）里，条目名 pen y 由 90 变 87 —— 位置只由 K 决定；
3. **反证**：`patch_zh85.py` 当年把 `0x565910` NOP 掉，条目名并没有跟着动（否则 GR_ZH85/86 就该修好它了）。

## 3. 区分判据（核心交付）

**判据 = `comp[0x44](H) == 20` 且 `comp[0x40](W) >= 400`**

| 判据 | 结果 |
|---|---|
| 只看 `fontID(comp[0x9C])==5` / 组件模板 `W=400 H=16 ax=33 ay=18` | ❌ 无效：这是**路径 A**（大标题）的字段，路径 B 的按钮根本不用它们；且前端列表行与 SF 列表行/条目条同为 `vtable=00595520`、同 `font`、同 `D9`/`4C`，无法区分 |
| 只看 `H == 20` | ❌ **实测不唯一**：K26 诊断盘 F11300 的 EE RAM 里 H==20 的按钮共 **48** 个 —— 1 个 `W=600`（本目标）+ 47 个 `W=34`/`W=20` 的小图标按钮。第一版补丁（仅 H==20）全帧回归立刻暴露：底栏 `△返回 / ✕查看` 的**图标**被误移 2px（y[395.4..407.7] → [393.3..405.6]） |
| 只看 `W == 600` | ⚠️ 可用但过窄（其它 SF 内页若模板宽度不同就漏修）；`W>=400` 既排除全部 47 个小图标（W=20/34），又对"整屏宽条目条"这一模板族成立 |
| **`H==20 && W>=400`** | ✅ 唯一命中该条目条模板；全帧回归零误伤（§5） |

> 判据在 cave 内以 2 条比较实现：`addiu $t4,$zero,20; bne $v1,$t4,keep21;` + `lw $t3,0x40($s2); sltiu $at,$t3,400; bne $at,$zero,keep21`（`$v1`=H 由 `0x21D93C` 载入、`$v0`=CharHeight 由 `0x21D934` 返回，均为调用点现成寄存器；`$t3/$t4/$at` 都是本函数内死寄存器）。

## 4. 补丁内容（字节级）

| VA | EN 原词 | ZH82 旧词 | 新词 | 说明 |
|---|---|---|---|---|
| `0x21D940` | `00621023` (subu) | `2462FFEB` | `08159680` | `j 0x565A00`（条件化 K） |
| `0x21D944` | `04410003` | `04410003` | `00000000` | 延迟槽改 `nop`（原 `bgez` 语义在 cave 内逐词复刻；该地址只由 `0x21D940` 落入，无其它 xref） |
| `0x565A00..0x565A48` | 全零 | 全零 | 19 词 | tail-cave（落点属 ZH58 复核过的 `0x56566E-0x56D7EF` 恒零填充区） |

```
0x565A00  addiu $t4,$zero,20          ; 判据①: H == 20 ?
0x565A04  bne   $v1,$t4,0x565A28      ;   否 → 保持 K=21
0x565A08  nop
0x565A0C  lw    $t3,0x40($s2)         ; W
0x565A10  sltiu $at,$t3,400           ; 判据②: W >= 400 ?
0x565A14  bne   $at,$zero,0x565A28    ;   否 → 保持 K=21 (排除 W=20/34 的小图标)
0x565A18  nop
0x565A1C  subu  $v0,$v1,$v0           ;   命中 → K = CharHeight (EN 原式)
0x565A20  b     0x565A2C
0x565A24  nop
0x565A28  addiu $v0,$v1,-21           ; ★ 认证 K=21 原词 (2462FFEB) 逐字保留
0x565A2C  bgez  $v0,0x565A3C          ; ↓ 以下 4 词 = 0x21D944/48/4C/50 逐词复刻
0x565A30  sra   $v1,$v0,1
0x565A34  addiu $v0,$v0,1
0x565A38  sra   $v1,$v0,1
0x565A3C  lui   $at,0x0021
0x565A40  ori   $at,$at,0xD954        ; ra = 0x21D954
0x565A44  jr    $at                   ; 回原流程 ($v1 = (H−K)/2)
0x565A48  nop
```

- 全盘差异 **53 字节**（挂点/延迟槽 7 B + cave 中非零的 46 B），脚本内白名单断言；
- 反汇编复核（capstone，见脚本输出）确认 `bne $v1,$t4` / `sltiu $at,$t3,0x190` / `bne $at,$zero` 三条判据跳转目标全部正确；
- **不重建 ISO**：只对现役盘打补丁（`shutil.copyfile` + 定位写 + 回读自验）。

## 6. 关于「同族」的澄清（写给用户/Lead）

- 「武器」大标题 = **路径 A**（`0x565900` cave `+7`），现役形态墨迹顶缘 25.5 vs EN 24.5，**只差 1px，量不出下沉**；
